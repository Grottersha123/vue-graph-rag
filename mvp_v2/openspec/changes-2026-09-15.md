## Change 1: add-dump-repair-restamp  — STATUS: IN PROGRESS (reviewer: REQUEST_CHANGES)

### proposal.md

#### Why
Пользователь вручную правит CSV внутри `runtime/dumps/dump-XXXXXX` (удаляет битые документы).
Дампы иммутабельны: `manifest.json` содержит sha256 каждого файла, `load_verified_dump`
отвергает любые правки ("hash mismatch"), а удалённые строки оставляют осиротевшие
ссылки ("graph invariants failed"). Нужен поддержанный путь: правка руками -> кнопка
"проверить и пере-подписать" с отчётом об удалениях ДО записи.

#### What Changes
- Новый `mvp_v2/src/mvp_v2/application/dump_restamp.py`:
  `plan_dump_restamp(path) -> RestampPlan` (read-only анализ) и
  `apply_dump_restamp(plan) -> RestampReport` (запись + верификация).
- UI: вкладка LadybugDB, блок "Repair manually edited dump":
  Check edited dump -> отчёт -> confirm -> Apply dump re-sign.
- Умеет: осиротевшие связи (каскад), битые артефакты-документы
  (все версии с sha256=="" и error!="" -> удалить документ целиком),
  починка заголовков пустых таблиц, канонизация CRLF.
- Отказывается работать (abort с причинам) при: неверном заголовке непустой
  таблицы, битых строках, активном документе без текущей "здоровой" версии,
  нечитаемом манифесте, невалидных инвариантах после ремонта.

#### Impact
- `mvp_v2/src/mvp_v2/application/dump_restamp.py` (новый)
- `mvp_v2/src/mvp_v2/presentation/app.py` (блок UI + session_state.restamp_plan)
- `mvp_v2/tests/test_dump_restamp.py` (новый, 7 тестов — зелёные)
- Риск данных: применениe перезаписывает CSV дампа — обязательны precondition-хеши
  и атомарность (см. открытые задачи).

### specs/dump-repair/spec.md

## ADDED Requirements

### Requirement: Plan before write
Система SHALL предоставлять read-only планирование ремонта дампа, которое
возвращает отчёт (удаляемые документы/строки/рёбра, заголовки к починке,
нужна ли пере-подпись) и НЕ изменяет файлы до явного подтверждения.

#### Scenario: Healthy dump
- **WHEN** plan_dump_restamp выполняется на консистентном дампе
- **THEN** план не aborted, report_lines пуст, ни один файл не записан

#### Scenario: Errored artifact document
- **WHEN** активный документ имеет только версии с sha256=="" и error!=""
- **THEN** план предлагает удалить документ каскадом (версии, чанки, ассеты,
  эмбеддинги, все связи) и валидирует candidate через validate_graph

#### Scenario: Unfixable state
- **WHEN** активный документ без текущей версии не является артефактом
  (есть "здоровая" версия без is_current) или заголовок непустой таблицы неверен
- **THEN** план aborted с точным списком проблем, файлы не изменяются

### Requirement: Safe apply
Применение плана SHALL быть защищено precondition-хешами всех наблюдённых
файлов и атомарной подменой через staging-каталог с сохранением пути отката.

#### Scenario: Stale plan
- **WHEN** между Check и Apply любой наблюдённый файл изменился
- **THEN** apply отказывается работать и исходные байты сохраняются

### Requirement: UI gate
UI SHALL показывать отчёт до записи, требовать явный confirm для удаляющих
операций и выполнять операцию через spinner-обёртку с логированием ошибок.

## Change 5: evolve-graph-schema-v2 — STATUS: DONE (commit 830dc17)

### proposal.md

#### Why

Текущей графовой схеме нужны summaries, отдельное описание Asset, summary embeddings и управляемые optional fields без ослабления strict Pydantic contracts.

#### What Changed

- `Document.summary`, `Chunk.summary`, `Asset.description`.
- `Embedding.summary_vector`; сохранённое поле `purpose` удалено, purpose выводится из owner relation.
- Новая relation `HAS_SUMMARY_EMBEDDING`.
- Текущая schema version: `mvp-v2-graph-v2`, 22 canonical CSV tables.
- Strict schema profile SHA включён в dump/database manifests и проверяется на runtime boundaries.
- На момент Change 5 verified graph-v1 layout мигрировался in-memory; эта совместимость полностью удалена последующим Change 7.
- Optional fields задаются в `src/mvp_v2/graph_fields.json`, имеют exact type/default и хранятся внутри модели в typed `CustomProperty`, но flatten в CSV/LadybugDB как обычные columns.
- Document-summary embeddings сохраняются в dumps, но не входят в active Ladybug ANN projection.

### specs/schema-v2/spec.md

#### Requirement: Strict extensible schema

Система SHALL принимать только configured optional fields типов `STRING`, `INT64`, `BOOLEAN`, `FLOAT_VECTOR` с typed default и SHALL отклонять unknown, duplicate, reordered или colliding fields.

##### Scenario: Missing optional column

- **WHEN** supported artifact не содержит configured optional column
- **THEN** reader материализует её declared default без принятия arbitrary extras

#### Requirement: Summary embedding ownership

Каждый current embedding SHALL иметь ровно одного typed owner через `HAS_EMBEDDING_CHUNK`, `HAS_EMBEDDING_ASSET` или `HAS_SUMMARY_EMBEDDING`.

##### Scenario: Document summary storage

- **WHEN** непустой Document.summary получает embedding
- **THEN** embedding сохраняется в canonical dump через `HAS_SUMMARY_EMBEDDING`, но active projection не индексирует его в текущем ANN Search/Chat

#### Retired requirement: graph-v1 migration

Это требование было реализовано в `830dc17`, затем отменено Change 7. Текущий loader отклоняет graph-v1 и 21-table artifacts.

## Change 6: add-document-version-upload-and-custom-columns — STATUS: DONE

### proposal.md

#### Why

Новые версии документов должны использовать один ingestion workflow, а внутренний `custom_properties` sidecar не должен протекать в UI. Preview нельзя коммитить после изменения формы, файлов или snapshot.

#### What Changes

- Upload остаётся основной ingestion surface.
- В Documents выбранный документ получает **Upload new version** dialog, который повторно использует общий Upload renderer.
- `IngestionRequest.document_id` явно фиксирует target; external ID в dialog синхронизирован с текущим Document и read-only.
- Текущие SourceType, Status, Process и Role используются как dialog defaults; repeat ingestion сохраняет существующий `Document.source_name`.
- Markdown и sibling images загружаются одним batch; новая версия получает собственные Asset nodes/paths, история не перезаписывается.
- Raw `custom_properties` скрывается; configured fields показываются отдельными read-only columns только своего node type.
- Preview связывается с input fingerprint и snapshot revision; stale/failed/reopened preview нельзя commit.

### specs/document-version-upload/spec.md

#### Requirement: One ingestion workflow

Система SHALL использовать один Upload renderer и один application ingestion service для обычной загрузки и добавления версии из Documents.

##### Scenario: Upload new Markdown version with images

- **WHEN** пользователь выбирает Document, открывает **Upload new version**, передаёт Markdown и referenced sibling images, выполняет Preview и Commit
- **THEN** создаётся следующая DocumentVersion того же exact Document, новые Assets принадлежат новой версии, а предыдущие version/files сохраняются

##### Scenario: Existing source metadata

- **WHEN** новая версия загружается для Document с непустым `source_name`
- **THEN** ingestion сохраняет существующий `source_name`, даже если shared form не редактирует это поле

##### Scenario: Changed document identity

- **WHEN** metadata external ID изменён после предыдущего открытия dialog
- **THEN** повторное открытие очищает старое widget state и показывает новый locked external ID

#### Requirement: Preview must match current inputs

Commit SHALL быть доступен только для preview, fingerprint которого совпадает с текущими полями, target Document ID, ordered upload names/content hashes и snapshot revision.

##### Scenario: Input changes after preview

- **WHEN** пользователь меняет title, relation, URL, файл или snapshot после успешного Preview
- **THEN** старый preview считается stale, Commit блокируется и требуется новый Preview

##### Scenario: Failed re-preview

- **WHEN** новый Preview завершился ошибкой
- **THEN** ранее успешный preview не восстанавливается и не может быть committed

#### Requirement: Type-specific custom columns

UI SHALL скрывать raw `custom_properties` и показывать каждое configured property как отдельную read-only колонку только таблицы объявленного node type.

##### Scenario: Document-only field

- **WHEN** `review_note` объявлен для Document
- **THEN** Documents показывает `review_note`, а Chunk, Asset и Embedding tables его не показывают

## Change 7: remove-all-legacy-loading — STATUS: DONE

### proposal.md

#### Why

Система больше не должна импортировать старый `mvp_data` или автоматически преобразовывать graph-v1 artifacts. Поддерживается только текущая schema v2, чтобы убрать двойной CSV contract и ложноположительные compatibility tests.

#### What Changes

- Удалены `adapters/legacy/`, legacy migration service/report DTOs и старый UI import workflow.
- Neutral `canonical_json_bytes` и `DumpRepository` перенесены из migration-named modules.
- CSV reader принимает только exact current 22-table registry set.
- Dump/DB manifests принимают только `mvp-v2-graph-v2`, ровно 22 table facts и SHA текущего schema profile.
- Удалены Asset headers `caption`/`llm_description` и persisted Embedding `purpose`; Asset использует `description`, retrieval purpose по-прежнему выводится из typed owner relation.
- Dump restamp ремонтирует только current-schema dumps и не синтезирует отсутствующую v2 relation.
- Вкладка `Errors/Import report` стала `Errors` без import controls.
- Legacy migration tests удалены; полезные filesystem resolver/dump numbering tests сохранены в current adapter suite.

### specs/current-artifacts-only/spec.md

#### Requirement: Current schema only

Runtime SHALL принимать только artifacts с `graph_schema_version=mvp-v2-graph-v2`, ровно 22 canonical tables и schema-profile SHA текущей конфигурации.

##### Scenario: Retired graph-v1 dump

- **WHEN** manifest объявляет `mvp-v2-graph-v1` или содержит 21 table fact
- **THEN** manifest validation отклоняет artifact до чтения graph rows

##### Scenario: Retired CSV headers

- **WHEN** Asset CSV содержит `caption`/`llm_description` или Embedding CSV содержит persisted `purpose`
- **THEN** current CSV reader отклоняет header; автоматическая миграция не выполняется

#### Requirement: Current-schema fresh start

- **WHEN** session snapshot не содержит SourceType или Status
- **THEN** Upload предлагает explicit **Initialize workspace**, которое добавляет только missing deterministic current-schema defaults без чтения файлов или публикации artifacts

#### Requirement: No old-data import surface

Application SHALL NOT содержать adapter, service или UI action для preview/approval/import старого `mvp_data` CSV tree.

##### Scenario: Errors tab

- **WHEN** пользователь открывает последнюю вкладку
- **THEN** она показывает только session errors/application log и не предлагает legacy import/report actions

#### Requirement: Preserve current behavior

Удаление compatibility code SHALL сохранять current dump publication, current dump restamp, versioned ingestion, retrieval-purpose filters и stable IDs.

## Change 8: add-rag-batch-debug-and-chunk-maintenance — STATUS: DONE

### Why

Нужны воспроизводимый batch-debug retrieval/LLM и безопасная возможность полностью пересобрать неудовлетворительные chunks без ручного редактирования graph tables.

### Requirements

#### Requirement: Batch RAG trace notebook

- **WHEN** пользователь запускает `notebooks/rag_batch_debug.ipynb`
- **THEN** notebook выбирает verified current-schema DB и exact source dump, запускает заданные вопросы через реальные `SearchService`/`ChatService` с configurable bounded worker count
- **AND** каждый run автоматически сохраняет git-ignored `YYYY-MM-DD/<UTC-run-id>/run.json` и `results.json` с evidence, score, metadata, prompt, raw model response, final answer, latency и error
- **AND** student refusal cases явно помечены как behavioral probes, а не как enforced authorization boundary

#### Requirement: Destructive chunk maintenance

- **WHEN** пользователь запрашивает regeneration preview
- **THEN** все старые chunks и только их embeddings удаляются из candidate snapshot, current Markdown sources повторно проверяются по SHA-256 и chunked текущей policy, а Asset и asset embeddings сохраняются
- **AND** non-Markdown current chunks блокируют regeneration вместо молчаливой потери
- **WHEN** пользователь запрашивает deletion preview
- **THEN** candidate удаляет все Chunk, HAS_CHUNK, CONTAINS_ASSET, HAS_EMBEDDING_CHUNK и owned chunk Embedding rows, сохраняя остальной граф
- **AND** commit требует impact preview, отдельный checkbox и актуальный snapshot revision

#### Requirement: Actionable and explicit Ollama transport

- **WHEN** Ollama возвращает HTTP error, timeout или connection failure
- **THEN** adapter сообщает безопасную bounded категорию и Ollama error detail без prompt payload
- **WHEN** base URL использует не-loopback host
- **THEN** host должен отдельно присутствовать в `MVP_V2_OLLAMA_ALLOWED_LAN_HOSTS`, все resolved addresses должны быть private/link-local, а connection закрепляется за одним validated IP без повторного DNS или proxy
- **AND** LAN HTTP документирован как явно принятый незашифрованный debug-режим
