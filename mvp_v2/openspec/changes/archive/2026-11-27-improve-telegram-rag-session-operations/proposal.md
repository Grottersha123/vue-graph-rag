# Proposal

## Why

Telegram-боту не хватает завершённого UX для выбора профиля, feedback и продолжения диалога. RAG иногда отвечает по нерелевантным документам, смешивает телефоны и не сообщает пользователю о fallback провайдера, а диагностика и экспорт логов требуют неудобных ручных действий.

## What Changes

- Завершить Telegram-сценарий выбора профиля: показать состояние ожидания вопросов после выбора и удалить кнопку профиля после успешного выбора.
- Сделать кнопку «Пропустить» явной: не удалять сообщение молча и отправлять понятное продолжение диалога.
- Добавить настраиваемое количество evidence в `.env.example` и конфигурационные проверки.
- Описать безопасное использование токенов: значения для локального запуска можно задавать через `.env`, а Compose secrets остаются предпочтительным production-вариантом; объяснить назначение `gateway_token`.
- Добавить режим `DEBUG`/`ERROR` для контейнерного логирования и сделать экспорт логов доступным без ручного вызова неудобной команды.
- Уточнить retrieval и исключить телефонные номера из RAG evidence, сохранив доступность подходящих legacy-документов без новых metadata.
- Добавить провайдера Selora через URL и API key, использовать его основным, выполнять fallback на Gemma при ошибке и сообщать о fallback в Telegram.
- Добавить приветствие при начале/возобновлении чата после периода без сообщений.

## Capabilities

### New Capabilities

- `telegram-conversation-ux`: явные состояния профиля, feedback, приветствия и таймаутов сессии.
- `rag-provider-fallback`: основной Selora-провайдер, fallback на Gemma и уведомление пользователя о деградации.
- `runtime-diagnostics-and-operations`: уровни логирования, evidence configuration и удобный экспорт логов.

### Modified Capabilities

- `curated-faq-rag`: retrieval SHALL учитывать временной и смысловой scope документов и не использовать нерелевантные персональные материалы как evidence.

## Impact

Затрагиваются Telegram controller/state/keyboards, backend RAG orchestration и provider adapters, retrieval filters, runtime configuration, `.env.example`, Compose/Makefile и документация эксплуатации. Потребуются новые configuration и integration checks; секреты не должны попадать в логи или git.
